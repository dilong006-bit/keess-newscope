## 0. 문서 규칙

- 본 문서는 확정 프로토타입을 기준(baseline)으로 한 **증분 PRD**다. 기준 기획안은 수정하지 않으며, 본 증분은 신규 스코프(keess-newscope)에 사회공헌 반영분과 **함께 빌드·배포**된다.
- 기능 ID는 본 증분에서 `C1`(Consistency) 접두로 시작한다 (사회공헌 트랙과 번호 충돌 방지).

## 1. 고도화 배경 — 기준 버전의 구조적 한계

1. **페이지 간 내비게이션 패턴 불일치**: 4개 서비스 페이지(/ax-ai, /leadership, /hrd, /content)가 동일한 "히어로 + 섹션 앵커 서브내비" 구조를 쓰면서도, 세부 패턴이 페이지마다 다르다. 실사 결과:

| 페이지 | 서브내비 숫자 접두어 | "맨 위로 ↑"(#top) |
|---|---|---|
| /ax-ai | 없음 | **없음 ← 문제** |
| /leadership | 없음 | 있음 |
| /hrd | 없음 | 있음 |
| /content | **01~06 있음 ← 문제** | (확인 대상) |

2. **/ax-ai의 상방 이동 어포던스 부재**: 서브내비 8개 항목(#scenario~#inq)은 전부 하방 이동만 제공한다. GNB 로고는 홈(/)으로 이동하므로 페이지 내 최상단('AX 전환교육' 히어로) 복귀 수단이 아니다. 긴 스크롤 페이지에서 사용자는 수동 스크롤 외에 돌아갈 방법이 없다.

> "새 패턴을 발명하지 않는다 — 이미 형제 페이지에 있는 패턴을 없는 페이지에 이식해 4개 페이지를 하나의 규칙으로 맞춘다."

## 2. 요구사항 분석 — 의도와 목적 해석

**[R1] /ax-ai 최상단 이동 수단 부재**
- 표면 요청: 8개 섹션으로 이동은 되는데 최상단 'AX 전환교육' 섹션으로 돌아갈 방법이 없다
- 진짜 의도: 긴 상세 페이지에서 탐색의 왕복성 확보 — 내려간 사용자가 페이지 정체성(히어로)으로 손쉽게 복귀
- 해결 문제: 하단 섹션(과정·문의)까지 내려간 사용자가 페이지 개요를 다시 보려면 수동 스크롤 필요, 형제 페이지 대비 경험 결손
- 성공한 모습: /ax-ai에서도 /leadership·/hrd와 동일하게 "맨 위로 ↑" 한 번으로 히어로 복귀. 4개 페이지 어디서든 같은 위치·같은 모양의 복귀 수단

**[R2] /content 서브내비 숫자 접두어**
- 표면 요청: 서브내비 라벨 앞 01~06 숫자를 다른 페이지처럼 제거
- 진짜 의도: 4개 서비스 페이지의 서브내비를 동일 문법으로 통일 — 사용자가 페이지를 오갈 때 학습 비용 0
- 해결 문제: /content만 번호가 붙어 "순서를 따라야 하는 단계"처럼 오독될 여지 + 시각적 이질감
- 성공한 모습: 4개 페이지 서브내비가 텍스트 라벨만으로 통일. 콘텐츠 본문의 의미 있는 넘버링(프로세스 스텝 등)은 유지

**요구사항 → 기능 매핑**

| # | 원 요구사항 | 매핑 기능 |
|---|------------|-----------|
| 1 | /ax-ai 최상단 복귀 수단 | **C1** 맨 위로 패턴 이식 |
| 2 | /content 숫자 접두어 제거 | **C2** 서브내비 라벨 정규화 |

## 3. 기능 명세

### C1 — /ax-ai "맨 위로 ↑" 패턴 이식 (Must)

- /leadership·/hrd에 이미 존재하는 "맨 위로 ↑"(href="#top") 링크를 **동일 마크업·동일 스타일·동일 위치(푸터 직전)**로 /ax-ai에 추가
- 페이지 최상단에 `#top` 앵커 대상 확보 (형제 페이지와 동일 방식)
- 스크롤 동작(smooth 여부)도 형제 페이지와 동일하게
- **비채택 대안과 사유**: ① 서브내비에 '소개' 항목 추가 → 8개 항목이 9개로 늘어 서브내비 밀도 악화, 형제 페이지에 없는 패턴이라 오히려 불일치 심화. ② 플로팅 TOP 버튼 → 4개 페이지 전체에 일괄 도입해야 할 신규 패턴으로 본 증분 범위 초과(후속 검토 항목으로 이관)
- **Done when**: /ax-ai 최하단 #inq에서 "맨 위로 ↑" 클릭 시 히어로가 뷰포트에 노출되고, 4개 서비스 페이지 모두 동일 위치에 동일 컴포넌트가 존재

### C2 — /content 서브내비 라벨 정규화 (Must)

- 서브내비 6개 항목에서 숫자 접두어 제거: "01 직무역량"→"직무역량" … "06 제작·파트너"→"제작·파트너"
- 동일 라벨이 반복되는 곳(모바일 메뉴, 섹션 헤딩에 같은 접두어가 있을 경우, aria-label)도 함께 정규화
- **제거 제외**: 콘텐츠 본문 성격의 넘버링(예: /hrd의 "01 · 기획·구성" 같은 SERVICE MODEL 스텝 표기)은 정보 구조상 의미가 있으므로 유지 — 이번 대상은 **내비게이션 라벨**에 한정
- 앵커 id(#ax1~#ax6)는 변경하지 않는다 (URL 해시 호환 유지, 텍스트만 수정)
- **Done when**: /content 서브내비에 숫자 접두어 0건, 앵커 이동 6건 전부 정상, 4개 페이지 서브내비 라벨 문법 통일

## 4. 데이터 모델 변경

없음 — 순수 마크업/라벨 수정. 마이그레이션·하위호환 이슈 없음.

## 5. 엣지 케이스 및 제약

- 반응형: 모바일에서 서브내비가 가로 스크롤/햄버거로 변형될 경우에도 C1·C2 동일 적용 확인
- 기존 제약 유지: 신규 색상·토큰 추가 금지, GNB 구조 변경 금지, 콘텐츠 문안 수정 금지(라벨 접두어 제거 외)
- C1의 #top 앵커 추가가 기존 "본문 바로가기"(#main) 스킵 링크와 충돌하지 않아야 함
