# KEESS 프로토타입 일관성 개선 기술명세서 v1.0

**작성일**: 2026-08-03
**상위 문서**: `KEESS_프로토타입_일관성개선_PRD_upgrade-01.md` (기능 ID C1·C2)
**대상 저장소**: keess-newscope (사회공헌 반영분과 동일 빌드 트레인)

---

## 1. 한줄요약

| 기능 | 수정 내용 | 예상 규모 |
|---|---|---|
| C1 | /ax-ai에 `#top` 앵커 + "맨 위로 ↑" 링크를 /leadership·/hrd와 동일 패턴으로 이식 | 파일 1개, ~5줄 |
| C2 | /content 서브내비 라벨의 "01 "~"06 " 접두어 제거 (앵커 id 불변) | 파일 1~2개, 문자열 6~18곳 |

핵심 원칙: **새 컴포넌트·새 스타일을 만들지 않는다.** 기준은 항상 형제 페이지의 기존 구현이며, 그것을 복사·이식한다.

## 2. C1 — /ax-ai 맨 위로 패턴 이식

### 2-1. 구현 절차

1. **레퍼런스 확인**: `app/leadership/page.tsx`(또는 /hrd)에서 "맨 위로" 구현을 찾는다 — ① `#top` 앵커가 걸리는 요소(페이지 래퍼 `id="top"` 또는 최상단 앵커 요소) ② "맨 위로 ↑" 링크의 마크업·클래스·삽입 위치(푸터 직전으로 확인됨)
2. **이식**: `app/ax-ai/page.tsx`에 동일한 두 요소를 동일 위치에 추가. 클래스·문구("맨 위로 ↑")·href("#top")를 레퍼런스와 문자 단위로 일치시킨다
3. **스크롤 동작**: 형제 페이지가 CSS `scroll-behavior: smooth`(전역) 기반이면 추가 작업 없음. JS 스크롤 핸들러를 쓴다면 동일 핸들러 재사용

### 2-2. 주의사항

- 기존 "본문 바로가기"(#main) 스킵 링크와 별개다 — #main을 #top으로 바꾸지 말 것
- 서브내비(8개 항목)는 손대지 않는다 — 항목 추가·삭제 금지
- 공통 레이아웃/푸터 컴포넌트에서 "맨 위로"가 조건부 렌더링되고 있을 가능성 확인: 만약 공통 컴포넌트가 페이지별 플래그로 노출을 제어하고 있다면, /ax-ai 플래그만 켜는 것이 정답 (페이지에 중복 마크업 삽입 금지)

## 3. C2 — /content 서브내비 라벨 정규화

### 3-1. 구현 절차

1. `app/content/page.tsx`(및 서브내비가 별도 컴포넌트/데이터라면 해당 파일)에서 라벨 원천을 찾는다 — 배열 데이터(`{ label: '01 직무역량', href: '#ax1' }` 형태)일 가능성이 높음
2. 라벨 문자열에서 접두어만 제거: `01 직무역량` → `직무역량` (6개 전부)
3. 동일 접두어가 쓰인 다른 위치 전수 확인: `grep -rn "01 직무역량\|02 어학\|03 IT\|04 비즈니스\|05 법정\|06 제작"` — 모바일 메뉴, 섹션 헤딩, aria-label, 메타 태그 포함
4. **앵커 id(#ax1~#ax6)와 href는 절대 변경하지 않는다** — 텍스트 라벨만 수정

### 3-2. 제거 범위 판단 기준

- 제거: **내비게이션 라벨**(서브내비, 모바일 내비, 같은 라벨의 aria-label). 섹션 헤딩에 동일 "01~06" 접두어가 붙어 있다면 그것도 제거(내비와 헤딩은 한 쌍)
- 유지: 콘텐츠 본문 내부의 의미 있는 넘버링 — 프로세스 스텝("01 · 기획·구성" 류), 순서형 카드 번호 등. 판단이 애매한 곳은 수정하지 말고 보고
