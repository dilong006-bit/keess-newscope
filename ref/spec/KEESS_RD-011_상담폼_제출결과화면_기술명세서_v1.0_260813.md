## 0. 착수 전 확인된 사실 — 구현 범위가 달라지는 지점

기준환경 홈 `#inq` 상담 폼을 실측한 결과입니다.

| 항목 | 기준환경 `keess-newscope.vercel.app` | 운영 `www.keess.co.kr` |
|---|---|---|
| 폼 UI | 있음 (`#inq` 섹션) | 있음 |
| 제출 API | **없음** (번들 내 `/api/` 경로 0건) | `POST /api/v1/open/keess/inquiry` |
| 완료 화면 | **없음** (`접수되었습니다` 0건) | 있음 |
| 오류 처리 | **없음** (`실패`·`오류`·`다시 시도` 각 0건) | 제네릭 1종 |
| 웹방화벽 | 없음 | **있음** — 차단 시 `200 OK` + `text/html` |

**따라서 이번 작업은 "오류 분기 추가"가 아니라 "제출 결과 화면 3종 신설 + 모의 제출 구축"이다.**
기준환경은 판정 기준(spec-by-example)으로 기능해야 하므로, **검수자가 실제로 `<script>`를 입력해 차단 화면을 확인할 수 있어야 한다.**

> **참고(별건)**: 기준환경과 운영의 필드명이 다릅니다 — `contactName`↔`manager`, `jobTitle`↔`position`, `expectedTrainees`↔`learners`, `message`↔`inquiry`. 운영이 기준환경을 그대로 승계하지 않고 재구현한 흔적입니다. 이번 범위 밖이나 별도 확인을 권고합니다.

## 1. 상태 머신

```
idle ──[상담 신청]──▶ submitting ──┬──▶ success          (접수 완료)
                                   ├──▶ blockedByFilter  (내용 때문에 막힘)
                                   └──▶ serverError      (일시적 서버 오류)

blockedByFilter ──[내용 수정하기]──▶ idle (입력값 보존, 문의 내용 필드로 포커스)
serverError     ──[다시 시도]────▶ submitting
success         ── 폼 영역을 완료 카드로 치환, 자동 닫힘 없음
```

## 2. 화면 사양

### 2-1. `success`

폼 영역을 완료 카드로 치환한다.

| 요소 | 값 |
|---|---|
| 아이콘 | lucide-react `check` (기존 성공 스타일 상속) |
| 제목 | **`문의가 접수되었습니다`** |
| 본문 | **`담당자가 영업일 1일 내 회신드립니다.`** |
| 액션 | **없음** (카드만 유지) |
| 자동 닫힘 | **없음** |

> 좌측 히어로 카피가 `1일 내 회신드립니다`이므로 본문을 이에 맞춘다. 리더십·조직(`담당자가 확인 후 연락드리겠습니다.`)과 문구가 다른 것은 의도된 페이지별 차이다.

### 2-2. `blockedByFilter` ★ RD-011 핵심

| 요소 | 값 |
|---|---|
| 아이콘 | lucide-react `alert-circle` |
| 제목 | **`입력하신 내용 중 일부는 접수할 수 없습니다`** |
| 본문 | **`` `<` `>` 기호나 코드 형태의 문장을 지운 뒤 다시 시도해 주세요.`` |
| 보조 | 작은 글씨 — **`어려우시면 02-000-0000 으로 연락 주세요.`** (전화번호는 확정값으로 교체) |
| 액션 | **`[ 내용 수정하기 ]` 버튼 1개** |

**엄수 규칙**

| # | 규칙 |
|:--:|---|
| 1 | **`일시적인`·`잠시 후 다시 시도` 문구 사용 금지** — 재시도해도 실패하므로 |
| 2 | **`스크립트`·`웹방화벽`·`필터`·`XSS`·`태그` 등 기술 용어 사용 금지** |
| 3 | **입력값을 지우지 않는다.** 해당 부분만 수정해 재시도할 수 있어야 함 |
| 4 | `내용 수정하기` 클릭 → 폼 복귀 + **`문의 내용`(`message`) 필드로 포커스 이동 및 스크롤** |
| 5 | 버튼은 **1개만**. 버튼 2개는 "폼으로는 안 되나 보다"로 읽혀 이탈을 부추긴다 |
| 6 | 전화번호는 **버튼이 아니라 작은 텍스트 1줄** |

### 2-3. `serverError`

| 요소 | 값 |
|---|---|
| 아이콘 | lucide-react `alert-circle` |
| 제목 | `일시적인 오류로 접수에 실패했습니다` |
| 본문 | `잠시 후 다시 시도해 주세요.` |
| 액션 | `[ 다시 시도 ]` |

### 2-4. 제출 전 사전 경고 (인라인)

`문의 내용`(`message`) 입력 중 아래 패턴이 감지되면 필드 하단에 인라인 안내를 노출한다.

- 감지 패턴: `<script`, `onerror=`, `javascript:`, `<iframe`, `<img` + `src=`
- 문구: **`코드 형태의 문장은 접수되지 않습니다. 내용을 풀어서 적어 주세요.`**
- **입력 자체를 막지 않는다. 경고만 한다.**
- 제출 버튼도 비활성화하지 않는다 (오탐 가능성 때문)

## 3. 판정 로직 — 운영 구현 계약

기준환경에는 실제 API가 없으므로 아래를 **`lib/inquiry/submit.ts` 상단 주석과 본 명세에 계약으로 명시**한다. 운영 저장소가 이 규칙을 그대로 구현한다.

```ts
// 운영 환경 판정 계약 (기준환경은 mock 으로 동일 결과를 재현한다)
//
// 웹방화벽 차단 시 응답: 200 OK + Content-Type: text/html
// → 상태코드만으로는 실패를 알 수 없으므로 Content-Type 으로 먼저 판정한다.
//
const ct = res.headers.get('content-type') || ''
if (!ct.includes('application/json')) return 'blockedByFilter'
if (!res.ok)                          return 'serverError'
return 'success'
```

**순서가 중요하다.** `res.ok` 를 먼저 보면 차단(200)이 성공으로 판정된다.

## 4. 모의 제출 (기준환경 전용)

### 4-1. 구조

```
lib/inquiry/
 ├─ types.ts        InquiryResult = 'success' | 'blockedByFilter' | 'serverError'
 ├─ submit.ts       submitInquiry(payload): Promise<InquiryResult>
 │                   - 운영 판정 계약을 주석으로 명시
 │                   - MOCK 모드면 submitMock 위임
 └─ submitMock.ts   기준환경 전용. 프로덕션 번들에서 분리되도록 동적 import
```

### 4-2. MOCK 활성 조건

`process.env.NEXT_PUBLIC_INQUIRY_MOCK === '1'` 일 때만 활성. 기준환경 Vercel 프로젝트 환경변수에 설정한다. **운영 빌드에서는 미설정 → 실제 fetch 경로.**

### 4-3. MOCK 판정 규칙

| 우선순위 | 조건 | 결과 |
|:--:|---|---|
| 1 | URL 쿼리 `?__inqState=success \| blocked \| error` | 해당 상태 강제 (검수자용) |
| 2 | `message` 에 WAF 트리거 패턴 포함 (`<script`, `onerror=`, `javascript:`, `<iframe`) | **`blockedByFilter`** |
| 3 | 그 외 | `success` |

- 2번 규칙 덕분에 **검수자가 실제로 `<script>alert('XSS')</script>` 를 입력해 차단 화면을 그대로 확인**할 수 있다. 릴리즈 체크리스트의 `입력 필드에 스크립트·특수문자 입력 시 오류 없이 안전하게 처리된다` 항목을 기준환경에서 판정할 수 있게 된다.
- 지연 시뮬레이션 600ms — `submitting` 상태 렌더를 확인하기 위함
- **개인정보를 어디에도 전송하지 않는다.** 콘솔 로그도 남기지 않는다

## 5. 접근성

| # | 항목 |
|:--:|---|
| 1 | 결과 카드 컨테이너 `role="status"` `aria-live="polite"` — 상태 전환 시 1회 안내 |

| 5 | 사전 경고는 `aria-describedby` 로 `message` 필드에 연결 |
| 6 | `prefers-reduced-motion: reduce` — 상태 전환 애니메이션 제거 |
