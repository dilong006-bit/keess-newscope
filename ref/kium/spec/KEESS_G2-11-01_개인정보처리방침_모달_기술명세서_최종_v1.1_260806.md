## 1. 목적 및 요구

1. Footer의 `개인정보처리방침` 링크(현재 `href="#"` placeholder)를 살려, 클릭 시 **부정훈련 예방 안내와 동일한 모달 경험**으로 처리방침 전문을 제공한다.
2. Footer의 `이용약관` 링크는 **삭제**한다 (8/6 확정 — 이용약관 페이지 미제작).
3. 회신 3번(다운로드 선택 동의 근거 조항 제15조→제22조+정보통신망법 제50조)의 **반영 상태를 코드·화면 양쪽에서 최종 검증**하고, 미반영이면 본 빌드에서 적용한다.
4. 결과물은 정보보호팀 최종 확인용 기획안의 실물 근거이므로, 전문 md의 【 】 미확정 표기는 **그대로 렌더**한다(검토자가 확정 필요 지점을 화면에서 인지하는 것이 의도된 상태).

### 1-1. 근거 조항 법리 구분 — 검수 시 혼동 금지 (중요)

| 동의 유형 | 올바른 근거 표기 | 판단 |
| --- | --- | --- |
| 다운로드 모달 **필수 동의** "개인정보 수집·이용 안내" (리스트 파일 제공 목적) | **「개인정보 보호법」 제15조** | 수집·이용의 일반 적법 근거. 정보보호팀 무지적 승인 — **유지가 정답. 절대 수정 금지** |
| 다운로드 모달 **선택 동의** "매월 최신 과정 리스트 이메일 수신 동의" (지속·광고성 발송) | **「개인정보 보호법」 제22조 + 「정보통신망 이용촉진 및 정보보호 등에 관한 법률」 제50조** | 선택·마케팅성 별도 동의(제22조) + 영리목적 광고성 정보 사전 동의(망법 제50조) — 회신 3번 지적 대상은 **이 절 하나뿐** |

> 화면 검수 시 필수 동의 전문(기본 펼침/접힘 상태)만 보고 "제15조가 남아 있다 = 미반영"으로 판단하면 오독이다. **선택 동의의 '전문 보기'를 열어** 도입부를 확인해야 한다. 또한 vercel 배포본은 최신 빌드 **재배포 이후** 상태여야 코드 반영이 화면에 나타난다.

## 3. 구현 명세

### 3-1. `data/privacy.ts` (신규)

```ts
// KEESS 개인정보처리방침 — 단일 소스(Single Source of Truth)
// 원본: ref/protection/KEESS_개인정보처리방침_전문_v1.0_260806.md (정보보호팀 회신 8/6 반영)
// 문구는 임의 수정 금지. 【 】 표기는 게시 전 확정 대상이며 검토 단계에서는 그대로 렌더한다.

export interface PrivacyBlock {
  type: 'p' | 'table' | 'list' | 'note';   // note = ※ 보충 문구
  text?: string;                            // p·note
  items?: string[];                         // list
  columns?: string[]; rows?: string[][];    // table
}
export interface PrivacySection { id: string; title: string; blocks: PrivacyBlock[]; }

export const PRIVACY_TITLE = '개인정보처리방침';
export const PRIVACY_INTRO = '주식회사 KG에듀원(이하 "회사")은 …'; // 원문 md 서문 그대로
export const PRIVACY_SECTIONS: PrivacySection[] = [ /* 제1조~제10조, 원문 순서·문구 그대로 전사 */ ];
```

**전사 규칙 (엄수)**
1. 원문 md의 **서문 + 제1조~제10조**를 순서·문구 그대로 옮긴다. 말미의 "[작성 근거 대조 — 게시 전 삭제할 내부 메모]" 섹션은 **전사 대상에서 제외**한다.
2. 표(제1조·제2조·제8조)는 `table` 블록, ※ 문구는 `note` 블록, 번호·불릿(제7조·제9조)은 `list` 블록. 조항 내 ①②③ 항은 `p` 블록 개행 유지.
3. **제8조만 예외적으로 다음 값 반영**(전략 D): 보호책임자 `임근성` / 연락처 `privacy_eduone@kggroup.co.kr` / 담당 부서 `【부서명 — 정보보호팀 확인 후 기입】`
4. 그 외 【 】 표기(제10조 시행일 【2026-08-13】 등)는 원문 그대로.
5. URL은 문자열로 두되, 외부 링크로 만들 경우 `target="_blank" rel="noopener"`.

### 3-2. `components/common/PrivacyModal.tsx` (신규)

- `common/Modal` 사용: `labelledBy="privacy-modal-title"`, `title={PRIVACY_TITLE}`, **`maxWidth={720}`** (제1조 4열 표 가독. 모바일은 기존 `pv-overlay` 반응형 상속).
- 본문: `.pv-body`에서 섹션 순회 — 조 제목 `h4.pv-h`, `p` 블록 `<p>`, `note`는 `p.pv-note`, `list`는 `ul.pv-list`, `table`은 `table.pv-table`(`<thead>`+`<tbody>`).
- 신규 클래스 금지. 표가 좁은 화면에서 넘칠 경우에 한해 래퍼 `div`에 `overflow-x:auto` 인라인 처리만 허용.
- 모달 열림 시 본문 스크롤 최상단 초기화(ReportModal `bodyRef.scrollTop = 0` 패턴).

### 3-3. `components/common/Footer.tsx` (수정 2곳)

**① 정책 링크 행 교체** — 현행:

```tsx
<a className="priv" href="#">개인정보처리방침</a>
<span>·</span>
<a href="#">이용약관</a>
<span>·</span>
```

변경:

```tsx
<button className="report-link priv" type="button" aria-haspopup="dialog"
        onClick={() => setPrivacyOpen(true)}>개인정보처리방침</button>
<span>·</span>
```

- `이용약관` 앵커와 **구분점 `<span>·</span>` 1개**를 함께 삭제 → 결과: "개인정보처리방침 · KG그룹 사회공헌 · 부정훈련 예방 안내 · 부정훈련 신고" (구분점 2개 연속 금지).
- 기존 `.priv` 시각 강조 유지(버튼에 병기). `report-link` 재사용으로 앵커→버튼 전환에 따른 시각 변화 없음.

**② 모달 마운트** — `const [privacyOpen, setPrivacyOpen] = useState(false);` 추가, ReportModal·ISMS Modal 옆에 `<PrivacyModal open={privacyOpen} onClose={() => setPrivacyOpen(false)} />`.

### 3-4. 회신 3번 — 다운로드 선택 동의 근거 조항 검증 및 (미반영 시) 적용

**검증 절차 (빌드 시 반드시 수행·보고):**
1. `data/consent.ts`에서 `CONSENT_TEXTS.download.optional.legalBasis`가 아래 문장과 **글자 단위 일치**하는지 확인:

2. `components/common/ConsentGroup.tsx`의 `ClauseText`가 `c.legalBasis ?? 기본(제15조) 문장`으로 분기 렌더하는지 확인.
3. 개발 서버에서 `/content` 다운로드 모달 → **선택 동의 "전문 보기" 클릭** → 도입부가 제22조+망법 제50조로 렌더되는지 확인. 같은 모달의 **필수 동의 도입부는 제15조 유지** 확인.

※ 2026-08-06 18시 실사 기준 1·2번은 **기반영 확인됨**(consent.ts 86~88행 `legalBasis` 지정, ConsentGroup 52행 분기). 따라서 통상 검증만으로 통과할 것이나, 어떤 이유로든 미반영·회귀 상태라면 위 문장·분기 구조를 그대로 적용한다(G2-11-01 기술명세서 최종 v2.0 §3-4와 동일 명세). **필수 4종(ld/hrd/dl.required/ct)의 제15조 도입부와 문구는 절대 수정 금지.**
