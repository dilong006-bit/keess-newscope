## 0. 진단 총평

공개교육 탭은 "일정을 보고 → 신청을 결심하는" **전환 지면**인데, 현재 화면은 ① 일정 테이블이 구조적으로 깨져 있고 ② 카드가 과정안내 탭의 컴포넌트를 재사용하면서 칩 중복·높이 불일치·과정명 이중 노출이 발생하며 ③ 일정 확인과 상담 신청 사이의 **동선이 끊겨** 있다. 시각 정비(P0)와 동선 재설계(P1)를 분리해 처리하고, v1.1에서 모집 상태 체계(P1)를 4종으로 확장한다.

## 2. 설계 원칙

**"원하는 과정과 일정을 10초 안에 찾고, 두 번의 클릭으로 상담폼에 도착한다."**

| # | 원칙 | 적용 |
|:--:|---|---|
| 1 | 일정이 주인공 | 일정 뷰가 먼저, 더 크게. 회차가 클릭 가능한 최소 단위 |
| 2 | 모든 회차는 CTA다 | 회차는 전부 "이 일정으로 상담" 진입점 — 단, **마감 회차는 예외**(§3-0) |
| 3 | 선택 정보는 유실되지 않는다 | 과정/일정 선택 → 상담폼 프리필로 전달 (§5) |
| 4 | 라벨은 변별 정보만 | 공통 칩 제거, 카테고리 1회, 상태 배지는 회차에만 |
| 5 | 아이콘은 스캔 속도를 위해 | 메타 정보의 시각 앵커로만 사용 (§6) |
| 6 | **상태는 행동을 지시한다** (v1.1) | 배지는 장식이 아니라 "지금 신청해도 되는가·서둘러야 하는가"의 답 — 상태마다 CTA·정렬·톤이 달라진다 |

## 3. 일정 뷰 재설계 — 매트릭스 폐기, 듀얼 리스트로

### 3-0. 모집 상태 배지 4종 체계 (v1.1 신설)

회차별 상태 값을 아래 4종 단일 enum으로 확정한다. 상태는 **운영자가 데이터로 지정**한다(자동 계산 없음 — 판단 기준만 운영 가이드로 고정).

| 상태 | 의미 (운영 지정 기준) | 색 톤 | 아이콘(Lucide) | CTA | 정렬 가중치 |
|---|---|---|---|:--:|:--:|
| 🟡 **모집중** | 신청 접수 중 · 개강 확정 전 (기본값) | 앰버(amber) 배경 + 진한 앰버 텍스트 | `circle-dashed` | 활성 「이 일정으로 상담 →」 | 2 |
| ✅ **개강확정** | 최소 인원 충족 · 개강 확정 | 그린(green) 배경 + 진한 그린 텍스트 | `circle-check` | 활성 「이 일정으로 상담 →」 | 1 (최상단) |
| 🔥 **마감임박** | 잔여석 소수 · 접수 마감 직전 | 레드/오렌지 배경 + 진한 레드 텍스트 | `alarm-clock` | **강조 CTA** 「마감 전 상담 →」(주황 filled) | 1 (개강확정과 동급) |
| ⛔ **마감** | 접수 종료 | 그레이 배경 + 중간 그레이 텍스트 | `circle-slash` | CTA 제거 → 보조 링크 「다음 회차 상담」(과정만 프리필, §5 경로 B) | 4 (최하단) |

**설계 규칙**

- **3중 부호화 필수**: 색 + 아이콘 + 텍스트를 항상 병기 — 색약 사용자도 상태를 구분한다. 배지 최소 크기 24px 높이, 텍스트 12~13px
- **마감임박은 유일한 강조 상태**: 지면 전체에서 레드 계열은 마감임박에만 허용한다. 희소성이 곧 주목도다 — 다른 요소(가격, 할인 등)에 레드 사용 금지
- **마감은 시각적 후퇴 + 기회 전환**: 행 전체 투명도 60% + 썸네일/텍스트 채도 저하, 그러나 **행을 숨기지 않는다** — "인기 있어서 마감됐다"는 사회적 증거(social proof)가 남은 회차의 전환을 돕는다. CTA 자리는 「다음 회차 상담」으로 대체해 이탈 대신 리드로 회수
- **접근성**: 배지에 `role="status"` 불요(정적 정보), 단 마감 회차의 CTA 제거 시 `aria-disabled` 버튼이 아니라 **링크 자체를 교체**한다(비활성 버튼은 스크린리더에 혼란)
- **상태 전이**: 모집중 → 개강확정 → 마감임박 → 마감 단방향 기본, 역전이(개강확정→모집중)는 데이터 수정으로만. 지난 날짜 회차는 상태와 무관하게 자동 '마감' 표기 처리(프론트 가드)

**상태 필터 칩** (상단 필터 바): `전체 19 · 🟡 모집중 n · ✅ 개강확정 n · 🔥 마감임박 n · ⛔ 마감 n` — 카운트 병기, 기본 선택은 '전체'(단, 마감은 리스트 최하단 정렬로 자연 강등)

### 3-1. 공통 프레임

- 상단 필터 바: 월 칩(전체·10월·11월·12월) + 카테고리 칩 + **상태 칩 4종**(§3-0)
- `과정별 | 일정순` 세그먼트 토글 유지
- 매트릭스(월=열) 테이블 폐기

### 3-2. 「일정순」 뷰 (기본값 권장) — 날짜 그룹 리스트

```
── 10월 ──────────────────────────────
📅 10.12(월)~13(화) · 2일
   [AI활용] 업무효율화: Agent 과정        14시간 · 700,000원/1인
   ✅ 개강확정                    [이 일정으로 상담 →]

📅 10.14(수)~15(목) · 2일
   [AI활용] 업무효율화: Data 과정         14시간 · 700,000원/1인
   🔥 마감임박 · 잔여 3석          [마감 전 상담 →]

📅 10.27(화) · 1일
   [비즈니스 역량] 전략적 비즈니스 협상 스킬  7시간 · 400,000원/1인
   ⛔ 마감                        다음 회차 상담 ↗
```

- 회차 = 1행. 날짜가 행의 첫 번째 시각 요소, 과정명·메타가 그 뒤
- 월 그룹 내 정렬: 개강확정·마감임박(가중치 1) → 모집중(2) → 마감(4), 동순위는 날짜순
- 마감임박 행은 잔여석 정보가 있으면 병기(`잔여 n석`) — 없으면 배지만
- 지난 회차는 자동 비노출(또는 '지난 일정' 접힘 처리)

### 3-3. 「과정별」 뷰 — 과정 행 + 회차 pill

```
[AI활용] 업무효율화: Agent 과정   14시간·2일 · 700,000원/1인
   회차:  (✅ 10.12~13)  (🔥 12.07~08)  (⛔ 09.01~02)
                              [과정 상세 ↓] [과정만 상담 →]
```

- 회차 pill에도 상태 아이콘+색 동일 적용, 마감 pill은 비클릭(회색·취소선 날짜)
- pill 클릭 = 해당 일정 프리필 상담 / 「과정만 상담」 = 일정 미정 상담

### 3-4. 반응형

- PC: 리스트 전폭 / TB·MO: 동일 구조 세로 스택 — 가로 스크롤 원천 차단
- 검수 케이스: 필터 결과 0건("해당 조건의 회차가 없습니다") · 1건 · 전체 · **상태 4종 각각 단독 필터**

## 4. 과정 소개 카드 — 실사 통일 + 구조 단일화

### 4-1. 카드 규격 (전 카드 동일 구조 강제)

| 순서 | 요소 | 규칙 |
|:--:|---|---|
| 1 | 실사 썸네일 | 전 과정 Unsplash 실사 · 4:3 고정 · `object-fit: cover` · 텍스트 합성 금지 |
| 2 | 카테고리 dot-칩 | 1회만 (C1) |
| 3 | 과정명 | 본문 타이틀 1회만 · `line-clamp: 2` + **min-height 2줄분** — 카드 리듬 통일 |
| 4 | 요약문 | `line-clamp: 2` + min-height 동일 원칙 |
| 5 | 메타 행 | 아이콘+텍스트: 대상 · 시간·일수 · 가격 (§6) |
| 6 | **최근접 회차 배지** (v1.1) | 카드에도 가장 임박한 회차 1건의 상태 배지+날짜를 노출 — `✅ 10.12 개강확정` — 카드 단계에서 이미 "언제"가 보이게 |
| 7 | 확장 시퀀스 | 카드 하단 chevron → 상세 패널(§4-2) |

- 높이 통일은 **텍스트 블록별 min-height(줄 수 고정)** 로 달성 — 카드 전체 `min-height` 고정 금지(모바일 1열에서 DF-024 결함 재생산)
- 그리드: PC 3열 / TB 2열 / MO 1열, `align-items: stretch`는 다열 구간에만

### 4-2. 과정 상세 패널 — 「교육일정」을 첫 번째 정보로

```
┌ 상세 패널 ──────────────────────────────┐
│ ① 교육일정 (최상단 고정)                  │
│    ┌──────────┐ ┌──────────┐ ┌──────────┐│
│    │📅 10.12(월) │ │📅 12.07(월) │ │📅 09.01(월) ││
│    │  ~13(화)·2일│ │  ~08(화)·2일│ │  ~02(화)·2일││
│    │ ✅ 개강확정  │ │ 🔥 마감임박  │ │ ⛔ 마감     ││
│    │[이 일정 상담]│ │[마감 전 상담]│ │ 다음 회차↗  ││
│    └──────────┘ └──────────┘ └──────────┘│
│ ② 메타 그리드: 대상·시간·정원·방식·가격     │
│ ③ 과정 요약·목표                          │
│ ④ 커리큘럼 모듈                           │
│ ⑤ [이 과정으로 상담하기] (일정 미정 CTA)    │
└─────────────────────────────────────────┘
```

- **회차 카드 스트립**이 상세의 첫 화면 — 날짜가 헤드라인, 상태 배지·회차별 CTA 내장. 상태별 CTA 규칙은 §3-0 그대로
- 회차 1개면 카드 1장, 회차 없으면 "다음 회차 준비 중 — 과정만 상담 가능" + ⑤ CTA
- 모바일: 회차 2장 이상이면 가로 스크롤 스냅(`scroll-snap-type: x mandatory`) — 잘린 카드가 다음 카드 존재를 암시

### 4-3. Unsplash 실사 썸네일 운영

| 항목 | 기준 |
|---|---|
| 규격 | 4:3 · 최소 800×600 · JPG/WebP · 300KB 이내 |
| 배치 | `public/images/kium/` · 파일명 = 과정 id · `thumbSrc` 값만 추가하면 이미지 모드 전환(기존 설계 재사용) |

## 5. 상담폼 프리필 — 선택이 유실되지 않는 동선

### 5-1. 진입 경로 3종

| 경로 | 진입점 | 프리필 내용 |
|:--:|---|---|
| A. 과정+일정 | 일정순 행 CTA · 과정별 회차 pill · 상세 회차 카드 CTA | 관심영역 `인재키움` 자동 선택 + 문의내용에 **과정명 + 회차 일정 + 상태** 자동 입력 |
| B. 과정만 | 「과정만 상담」·상세 하단 CTA·**마감 회차의 「다음 회차 상담」**(v1.1) | 과정명 + "일정 협의 희망" (마감 진입 시 "마감 회차: ○월 회차 — 다음 회차 문의" 명시) |
| C. 일정만 | 월 그룹 헤더 「이 시기 교육 상담」 | "10월 개강 과정 상담 희망" |

### 5-2. 프리필 규격

- 이동: 앵커 스크롤 + URL 쿼리(`?course=kium-03&session=2026-10-12`) — **새로고침·링크 공유에도 유지**
- 문의내용 자동 입력 문안(수정 가능한 실제 value로 주입 — placeholder 금지):

```
[공개교육 상담 신청]
· 과정명: 업무효율화: Agent 과정
· 희망 회차: 10.12(월) ~ 10.13(화) · 2일 (개강확정)
· 문의 내용:
```

- 관심영역 `인재키움` 칩 자동 선택(해제 가능)
- 폼 상단 확인 배너: `📋 '업무효율화: Agent 과정 · 10.12~13 회차' 상담으로 작성 중입니다 [변경]`
- 접근성: 프리필 진입 시 포커스 폼 첫 필드 이동 + `aria-live` 안내
- **마감 회차 가드**(v1.1): 프리필 URL의 session이 마감 상태면 배너를 "해당 회차는 마감되었습니다 — 다음 회차 상담으로 접수됩니다"로 전환(경로 B 문안 적용) — 공유된 옛 링크로 들어온 사용자의 오신청 방지

## 8. 상태별 UI 검증 빌드 계획 (v1.1 신설)

"4종 상태의 UI를 화면에서 직접 확인"이 요구 사항이므로, 검증을 우연에 맡기지 않고 **빌드 자체에 검증 장치를 내장**한다.

### 8-1. 시드 데이터 원칙 — 4종 전 상태를 실화면에 상시 재현

| # | 원칙 | 내용 |
|:--:|---|---|
| 1 | **상태 커버리지 강제** | 프로토타입 시드 데이터의 회차 배정 시 4종 상태를 **각 2건 이상** 포함 — 일정순 뷰·과정별 pill·상세 스트립·카드 최근접 배지 4개 표면 모두에서 전 상태가 최소 1회씩 노출되도록 배치 |
| 2 | 한 과정에 다중 상태 | 최소 1개 과정은 회차 3개(개강확정+마감임박+마감)를 함께 보유 — 상세 스트립에서 상태 혼재 화면을 직접 확인 |
| 3 | 경계 케이스 포함 | 잔여석 있는 마감임박 1건 + 잔여석 없는 마감임박 1건 / 회차 0개 과정 1건("다음 회차 준비 중") |

### 8-2. 상태 쇼케이스 — QA·디자인 리뷰용 미리보기

- 개발 환경 전용 쿼리 스위치 `?preview=badges` 진입 시, 페이지 최하단에 **상태 배지 쇼케이스 블록** 렌더:
  - 4종 배지 원형(배지 단독) · 일정순 행 4종 · 회차 pill 4종 · 상세 회차 카드 4종 · 마감 가드 배너 — 한 화면 비교
  - 프로덕션 빌드에서는 미노출(개발 플래그 가드)
- 목적: ① 디자인 검수 시 상태를 만들려고 데이터를 고칠 필요 없음 ② 색 대비(WCAG AA 4.5:1) 확인을 4종 나란히 놓고 1회에 수행 ③ 향후 상태 스타일 회귀 검수 기준 화면

### 8-3. 검증 체크리스트 (완료 조건에 편입)

- [ ] 4종 상태가 일정순 행·과정별 pill·상세 회차 카드·카드 최근접 배지 4개 표면 전부에서 육안 확인됨
- [ ] 마감임박 CTA(강조 filled)와 일반 CTA의 시각 위계 구분 확인
- [ ] 마감 회차: 행 후퇴(투명도·채도) + CTA가 「다음 회차 상담」으로 교체 + pill 비클릭 확인
- [ ] 배지 4종 전건 색 대비 AA(4.5:1) 통과 — 텍스트/배경 실측
- [ ] 마감 회차 프리필 URL 진입 시 가드 배너 전환 확인
- [ ] 상태 필터 칩 4종 각각 단독 적용 시 카운트·결과 일치
- [ ] 그레이스케일(색상 제거) 화면에서도 4종 상태 구분 가능 — 아이콘·텍스트만으로 판별
